# Solo Audito

A Flutter mobile client for the existing AuditoAI backend, targeting Android, iOS and Chrome preview. Existing backend and web services are unchanged.

Phase one includes session restoration, login/register, responsive dashboard, bottom navigation, persisted system/light/dark themes, account profile, and initial chat with citations, loading, manual retry and existing conversation reopening. Document upload/processing, PDF viewing, onboarding and advanced history management are deferred. There are no fake responses or sample accounts in the app. Password recovery is unavailable in the existing backend.

## Requirements and installation

Created with Flutter stable **3.47.2 / Dart 3.13.2** using `flutter create --platforms=android,ios,web --org online.auditoai --project-name solo_audito solo-audito`. Use this SDK version or a compatible newer stable release; dependency versions are locked in pubspec.lock.

The SDK installed for this workspace is `~/development/flutter`. In your terminal:

```bash
export PATH="$HOME/development/flutter/bin:$PATH"
cd "$HOME/Downloads/legal(1)/AUDITO/solo-audito"
flutter pub get
flutter run -d chrome
```

Add that PATH export to your shell configuration if you want it available in future terminals. See [Flutter installation](https://docs.flutter.dev/install/manual) for other machines.

## Configuration and running

`API_BASE_URL` is an HTTP(S) **origin without `/api`**. Every path is centralized in `lib/core/config/api_config.dart`. No server secrets belong in dart-defines.

```bash
# Root Docker Compose gateway (host port 80); also the default
flutter run -d chrome --dart-define=API_BASE_URL=http://localhost

# Backend running directly on host port 8000
flutter run -d chrome --dart-define=API_BASE_URL=http://localhost:8000

# Production origin inferred from the existing ingress; verify deployment before use
flutter run -d chrome --dart-define=API_BASE_URL=https://auditoai.online

flutter devices
flutter run -d <device-id> --dart-define=API_BASE_URL=https://auditoai.online
```

Login requires a reachable existing backend and an AuditoAI account. The app itself opens to login without a backend. Existing conversations with indexed documents are usable; a new conversation cannot answer until documents are uploaded via AuditoAI web. Mobile upload is deferred.

Chrome needs a secure context (HTTPS or localhost) for secure storage. A web page served over HTTPS must use an HTTPS API. Browser CORS remains the existing backend's responsibility. Flutter secure storage on web uses browser storage/WebCrypto; native device key storage guarantees do not apply to browser previews. Keep preview origins/ports stable to retain the same stored session.

## Android

Install Android Studio, Android SDK and an emulator, then:

```bash
flutter doctor -v
flutter doctor --android-licenses
flutter emulators
flutter emulators --launch <emulator-id>
flutter devices
flutter run -d <android-device-id> --dart-define=API_BASE_URL=http://10.0.2.2
```

`10.0.2.2` is the standard Android emulator route to the host; append `:8000` for a directly exposed backend. Physical devices need a reachable HTTPS origin or host LAN address. Internet permission is configured and Android backup is disabled to avoid restoring unusable encrypted tokens. Plain HTTP is allowed only in the Android debug manifest; release builds should use HTTPS. Review the generated application ID and signing setup before a store release. No Android SDK/device was present during initial implementation; execution results are recorded in DEVELOPMENT.md.

## iOS

`ios/` is generated by Flutter CLI. Build on macOS with Xcode and the platform tooling required by `flutter doctor`. Open `ios/Runner.xcworkspace`, select a development team, review the bundle identifier, configure signing, and use an HTTPS API. Native secure storage uses Keychain; Runner.entitlements is wired into all three build configurations. Validate keychain access and persistence on a signed device before release. iOS building/signing is not available on Ubuntu. See [Flutter platform setup](https://docs.flutter.dev/platform-integration).

## Structure

```text
lib/
  main.dart, app.dart
  core/         config, network, storage, theme, routing
  features/     auth/{data,domain,presentation}, chat/{data,domain,presentation}
                splash, home, documents, history, profile
  shared/       reusable widgets
android/ ios/ web/   generated platform hosts
assets/             asset guidance
test/              API contract and widget tests
```

Only add additional layers/directories when used. `file_picker` will be added with the document-upload phase; current dependencies are Riverpod, Dio, GoRouter, Flutter Secure Storage, Shared Preferences, and the standard Cupertino icon font for iOS-adaptive controls.

```bash
flutter analyze

```
